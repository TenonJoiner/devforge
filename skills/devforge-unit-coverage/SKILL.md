# devforge-unit-coverage — 单元测试覆盖率达标

## 概述

执行单元测试 → 收集覆盖率 → 对比阈值 → 未达标定位遗漏分支补测 → 重跑，循环到达标。

本 skill 是覆盖率工具的调度器——**不自行拼凑覆盖率命令，不根据变更文件自行筛选测试范围**。项目上下文（CLAUDE.md / rules）需声明两项：

- **覆盖率命令**（脚本 / make target / npm script 等形式不限）——接受可选 diff 范围参数
- **覆盖率数据路径**——命令产出结构化覆盖率数据的位置

skill 只负责查找并调用命令、读取数据。默认只检测并输出覆盖率验收报告。带 `autofix` 参数时自动补测遗漏分支并回归，最多 5 轮。

## 何时使用

- spec-driven 工作流 QA 阶段的 UNIT-COVERAGE 任务
- 验证当前分支新增代码的单元测试覆盖率是否达标
- 覆盖率未达标时定位遗漏分支并补测

## 与 tdd-workflow 的边界

| 维度 | devforge-tdd-workflow | devforge-unit-coverage |
|------|----------------------|------------------------|
| 阶段 | 开发期（SCENARIO 任务） | QA 期（UNIT-COVERAGE 任务） |
| 驱动 | 行为驱动（RED→GREEN→REFACTOR） | 度量驱动（覆盖率对比阈值） |
| 测试时机 | 先写失败测试，再写生产代码 | 生产代码已存在，补遗漏分支 |
| 粒度 | 单个 Scenario 行为 | 变更范围内代码的覆盖率 |

**核心原则**：本 skill 的补测是**度量驱动的增量补遗漏**，针对覆盖率数据指出的未覆盖分支（错误处理、边界值、防御性分支）。不推翻 TDD 重写核心逻辑，不为达标删改被测代码。

**补测判定逻辑**：针对遗漏分支写一个触发该分支的测试并运行——
- 测试通过 → 代码逻辑本就正确，只是之前未测到，补齐覆盖
- 测试失败 → 暴露了 TDD 主流程遗漏的隐藏 bug；此时遵循"测试已先行（已失败），再修代码使其通过"的纪律修复

## 职责边界

- ✅ 执行单元测试并收集覆盖率
- ✅ 解析覆盖率数据，统计行/分支/函数覆盖率
- ✅ 对比阈值判定达标/未达标
- ✅ `autofix` 模式下补测遗漏分支并回归
- ❌ 不做开发期行为驱动测试 → 归属 `/df:tdd`
- ❌ 不做编译/lint 检查 → 归属 `/df:lint`
- ❌ 不做深度代码评审 → 归属 `/df:code-review`
- ❌ 不为达标删改被测代码以降低覆盖难度
- ❌ 不引入 skill 未定义的覆盖率工具或检查步骤
- ❌ 不根据变更文件自行筛选文件或拼凑覆盖率参数——范围控制由项目脚本负责

## 范围确定

优先级从高到低：

1. **`diff-range` 参数存在**：调用 `<覆盖率命令> <diff-range>`
2. **`full` 参数存在**：调用 `<覆盖率命令>`（不传 diff 范围），统计全仓覆盖率
3. **都不传**（默认）：探测基线分支（`origin/main` → `origin/master` → `main` → `master`），计算 `git diff <base>...HEAD`，调用 `<覆盖率命令> <diff 范围>`

> **代码就绪由调用方负责**：skill 不做 `git checkout`、`git fetch` 等操作。调用方负责确保工作目录位于正确的分支上。
> `diff-range` 由调用方注入，skill 不解析、不修改，直接作为参数传给覆盖率命令。

## 第 1 阶段：定位

### 步骤 1：定位覆盖率命令与数据路径

从 CWD 的 CLAUDE.md、README、项目 rules、构建/测试说明文档中查找已定义的覆盖率命令与覆盖率数据路径。

**未找到则停止**，提示用户在项目上下文显式配置。禁止自行探测构建系统、推断语言、拼凑候选命令。

**命令契约**：项目覆盖率命令必须满足——
- 接受可选的 diff 范围参数；不传时输出全仓覆盖率（行/分支/函数），传入时只输出该范围内新增代码的覆盖率
- 产出结构化覆盖率数据到项目上下文声明的数据路径
- diff 交叉分析通常由 `diff-cover` / `go-cover-diff` / `jacoco-diff-coverage` 等工具实现，具体选型由项目决定

### 步骤 2：确定覆盖率阈值

优先级从高到低：
1. 项目上下文（rules / CLAUDE.md）中的显式覆盖率阈值定义
2. 内置默认值：行覆盖 90% / 函数覆盖 80% / 分支覆盖 70%

阈值来源 MUST 在报告中显式标注。diff 模式下阈值作用于新增代码，`--full` 模式下作用于全仓。

## 第 2 阶段：执行与收集

**步骤 3**：调用项目覆盖率命令执行并收集
- `--full` 模式：`<覆盖率命令>`（不传 diff 范围）
- 默认 / `diff-range` 模式：`<覆盖率命令> <diff 范围>`
- 命令的 stdout/stderr 由 skill 用 shell 重定向捕获到 `/tmp/coverage-run-<索引>.log`（排错日志，如 `<命令> > /tmp/coverage-run-<索引>.log 2>&1; echo "EXIT=$?"`），禁止依赖 harness 自动持久化；脚本无需感知该日志路径
- 覆盖率数据从项目上下文声明的**数据路径**读取，不依赖 stdout
- 覆盖率按工具默认**全报**（行/分支/函数）

## 第 3 阶段：解析与判定

**步骤 4**：解析覆盖率数据并定位未覆盖单元

派遣 `tester` agent 读取项目上下文声明的数据路径，按数据实际格式（lcov / cobertura XML / jacoco XML / coverprofile / JSON 等）提取覆盖率信息，并定位未覆盖单元。

agent 返回归一化结果（**不返回完整数据正文**）：
- 范围内行/分支/函数覆盖率（百分比）
- 未覆盖项清单（`文件:行` + 分支类型）

数据不存在、格式无法识别或解析失败时，agent 报告失败原因，skill 停止。

**步骤 5**：对比阈值

| 结果 | `autofix` 未设置 | `autofix` 已设置 |
|------|-----------------|------------------|
| 行/分支/函数均达标 | 生成验收报告，通过，结束 | 生成验收报告，通过，结束 |
| 任一维度未达标 | 生成验收报告并附未覆盖项清单，结束 | 进入第 4 阶段 |

## 第 4 阶段：补测循环（仅 autofix）

**步骤 6**：派遣 `developer` agent 取步骤 4 返回的未覆盖项清单，按「补测判定逻辑」逐个补测试

**步骤 7**：重新执行步骤 3（覆盖率命令内部跑全量单测，含新补用例并生成新数据），回到步骤 4 重新解析
- 轮次上限 5 轮，超出则停止并在报告中列出剩余未覆盖项

## 输出格式

所有模式下生成覆盖率验收报告。提供 `report-output-path` 则写入该路径，否则使用 `/tmp/unit-coverage-<YYYYMMDD-HHMMSS>.md`，每次生成新文件不覆盖历史。

**生成验收报告前 MUST 读取模板文件**，按其章节结构、占位符与自检清单严格生成，禁止凭记忆推测格式。

模板查找（按优先级）：
1. `<skill_base_dir>/templates/coverage-report.md`
2. `find ~/.claude/plugins/ -name coverage-report.md`
3. 仍未找到 → 报错终止，报两个候选路径供人工确认

**生成验收报告后 MUST 对照模板末尾自检清单逐项验证**，全部通过方可视为完成，未通过则修正后重新验证。此为硬门控。

## 出口标准

- [ ] 行/分支/函数覆盖率均达标（≥ 阈值）
- [ ] 补测循环不超过 5 轮
- [ ] 验收报告已生成且通过模板自检清单
- [ ] 每条未覆盖项闭环：已补测 / 判定低价值不补（注明理由）/ 超出轮次上限
- [ ] 阈值来源已显式标注
- [ ] 范围模式已显式标注（diff / full / diff-range 注入）

## 红旗清单

| 红旗 | 触发条件 | 处理方式 |
|------|---------|---------|
| 🚩 覆盖率命令未配置 | 项目上下文未定义覆盖率命令 | 停止，提示用户在项目上下文配置，禁止自行探测 |
| 🚩 数据路径未配置 | 项目上下文未定义覆盖率数据路径 | 停止，提示用户声明数据路径 |
| 🚩 基线分支探测失败 | 默认模式下 `origin/main`、`origin/master`、`main`、`master` 均不存在 | 停止，提示用户通过 `--diff-range` 显式指定范围 |
| 🚩 补测死循环 | 5 轮后仍未达标 | 停止，输出剩余未覆盖清单 |
| 🚩 为达标删改被测代码 | 通过删除/改写被测代码降低覆盖难度 | 驳回，禁止篡改被测代码 |
| 🚩 补测演变为重写 | 补测演变为推翻 TDD 重写核心逻辑 | 停止，只允许增量补遗漏分支 |
| 🚩 阈值来源不明 | 报告未标注阈值来源 | 补注来源后重新验证 |
