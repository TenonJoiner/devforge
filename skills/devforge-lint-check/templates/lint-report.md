## 示例报告

以下为一份完整的最终报告示例（clang-tidy，C 项目）：

# Lint 检查报告：未提交变更

## L1 编译检查

| 命令 | 结果 |
|------|------|
| `make build` | PASSED |

## L2 Lint 分析

| 命令 | 结果 |
|------|------|
| `make lint` | 3 条告警 |

### 需修复（1 条）

#### MEDIUM（1 条）

**1. [src/io.c:89] narrowing conversion from 'ssize_t' to 'int'**

- **问题**：read() 返回 ssize_t，在错误路径中返回 -1。强制转换为 int 后错误码信息丢失，调用方无法区分 EOF 和错误。
- **修复**：将变量类型从 int 改为 ssize_t，并在调用方同步修改类型。
- **规则**：bugprone-narrowing-conversions（禁止可能导致数据丢失的类型缩窄转换）\| **级别**：MEDIUM

```c
    char buf[4096];
    ssize_t n = read(fd, buf, sizeof(buf));
→   int n2 = (int)n;  // 错误码 -1 被截断
    if (n2 < 0) {
```

### 已排除（2 条：误报 1 条，抑制 1 条）

- **误报**：clang-analyzer-core.UndefinedBinaryOperatorResult 1 条 — buf 在 138 行已通过 memset 初始化，分析器未跟踪该模式
- **抑制**：readability-redundant-cast 1 条 — cast 前后类型相同，属于死代码但无实际危害

## 自检清单

生成报告后必须逐项自检，全部通过才能视为报告完成：

- [ ] 范围声明为 `全量` / `未提交变更` / `MR` 三者之一，非占位符
- [ ] L1 所有构建命令均已执行且有明确结果（PASSED / FAILED）
- [ ] L1 FAILED 时报告在 L1 终止，无 L2 内容
- [ ] L1 通过时 L2 所有 lint 命令均已执行，结果明确（零告警通过 或 N 条告警）
- [ ] L2 零告警时只输出命令结果行，无"需修复/历史遗留/已排除/规则建议"段落
- [ ] 需修复/历史遗留按级别分组为 `#### CRITICAL` / `#### HIGH` / `#### MEDIUM` / `#### LOW` 四级子节，无对应级别的分组不出现
- [ ] 同级别内条目按文件路径排序
- [ ] 条目编号为各子节内自增的纯数字（`**1.**`、`**2.**`），**禁止**使用自定义前缀（如 FW-、HL- 等）
- [ ] 需修复/历史遗留每条均包含：文件:行号、问题说明、修复建议、规则名+含义、级别、源码片段
- [ ] 源码片段中告警行以 `→` 标注，上下文各 2 行
- [ ] 已排除按规则归类合并（误报/抑制分别汇总），不逐条列出
- [ ] 级别字段使用 CRITICAL/HIGH/MEDIUM/LOW，非工具原始级别
- [ ] 历史遗留条目包含"不阻塞本次合并"标记
- [ ] 规则建议仅列出"屏蔽"和"新增"，无"保留"项
- [ ] 报告使用 markdown 标题（`#`、`##`、`###`）组织层级，禁止整篇包裹在 ``` 代码块中
- [ ] 不存在"待确认""疑似""可能是""需要进一步分析"等未完成结论
